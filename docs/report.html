2. The application

A Spring Boot REST API with GET /api/v1/{add,subtract,multiply,divide}?a=&b= and Actuator's /actuator/health. Success returns {"operation":"add","a":2.0,"b":3.0,"result":5.0}. A missing or non-numeric parameter, NaN/Infinity, an overflowing result, and division by zero all return HTTP 400 with a structured body (timestamp, status, error, message, path) from one @RestControllerAdvice. Arithmetic lives in CalculatorService, apart from the HTTP layer.

Tests (38, all passing): 29 plain JUnit 5 unit tests of the service (5 cases per operation, divide by zero and negative zero, non-finite inputs, overflow); 7 MockMvc tests of the web layer (every operation and every error path); 2 tests on a real embedded server (health is UP, add returns 5.0). Surefire writes JUnit XML for Jenkins. JaCoCo measures 90% instruction and 100% branch coverage and fails the build below 85%.

Re-runnable and idempotent: disableConcurrentBuilds() allows one deploy at a time; compose up only replaces containers whose image changed. Measured: during a redeploy (build 5) 146 of 146 requests to the API succeeded. A deliberately broken replay (build 6) deployed tag 6, failed the smoke test, and was rolled back to tag 5 automatically.

Containerization

  • Dockerfile: stage 1 maven:3.9-eclipse-temurin-21 copies pom.xml and runs dependency:go-offline before copying src (dependency layer cached); stage 2 eclipse-temurin:21-jre-alpine copies only the JAR, runs as non-root user spring, EXPOSE 8080, HEALTHCHECK, exec java so the JVM gets SIGTERM, heap sized to the container (MaxRAMPercentage=75). Base images pinned by sha256 digest. .dockerignore keeps target/, .git/, docs and .env out. Image: 95 MB (docker image inspect). Runs alone with docker run -p 9090:8080 paradox73/calculator-app.
  • docker-compose.yml: network calc-net; two API services from one YAML anchor (health check on /actuator/health, restart: unless-stopped, environment variables, 512 MB limit); Nginx reverse proxy as the only host port (8081), started only when both replicas are healthy. One docker compose up starts the full stack.

Version control

Progressive commits on main (skeleton → service → tests → controller → Docker → Compose → Jenkinsfile → README), then four feature/fix branches merged through pull requests #1–#4 with merge commits. .gitignore excludes target/, IDE files and every secret file; Jenkins secrets live only in the gitignored jenkins/.env.

4. Challenges faced

ProblemCause and fix
Redeploy dropped requests (8 of 48 failed)compose up recreated both replicas at once. Fix: two services and a rolling update. A first attempt still failed about 40% of requests: the new replica was healthy in 4 s, before Nginx had re-resolved its address, so both were unreachable together. Fix: 1 s DNS refresh, 1 s connect timeout, 10 s pause between replicas. Result: 0 failures.
Nginx health check never passedlocalhost in Alpine resolves to IPv6 ::1; Nginx listens on IPv4 only. Fix: probe 127.0.0.1.
Push reached Jenkins but no build startedConfiguration as Code re-creates the job on every Jenkins start, wiping the triggers the first run registers. Fix: declare githubPush() and pollSCM in the job definition too (PR #3).
Jenkins in a containerBind-mounted nginx.conf resolves on the host, not in the Jenkins workspace → config baked into an Nginx image. localhost in Jenkins is the Jenkins container → Verify Health uses host.docker.internal.
Webhook needs a public URLJenkins runs on a laptop. A Cloudflare quick tunnel gives it an HTTPS address; jenkins/update-webhook.sh repoints the GitHub webhook after each restart. Polling remains as fallback.
Failure email crashedattachLog in email-ext needs the matrix-project plugin; added to plugins.txt.
